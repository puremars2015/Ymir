# 開發進度留言版

用留言版的方式記錄 Ymir / Vibe Maker 的開發進度。每個 Sprint 一個看板，人和 AI 都在這裡回報進度、提出問題、回覆決定。
因為本專案全由 AI 開發，這裡也是**不同 AI session 之間交接**的地方：新 session 開工前先讀最新看板，收工前留言回報。

## 留言規則

1. **新留言放在「💬 留言區」最上方**（最新的在最上面），編號接續該看板最大的編號。
2. **不修改別人的留言**。要更正或補充，請用「回覆」。
3. **📌 置頂區**只放該 Sprint 的狀態總覽（工作項目清單），任何人都可以直接更新勾選狀態。
4. **AI 每次工作結束前必須留言**：做了什麼、驗證結果（實際跑過的指令與結果）、卡關或需要決定的事。沒驗證的事要明說沒驗證。
5. 需要人決定的事，標上 `❓待決定`，並在內容最後留「回覆區」；決定後由回覆者或下一個 session 把結果補到置頂區。
6. 細節放在對應文件（ADR、開發規劃、README），留言只寫摘要並附連結，避免同一件事寫兩份。
7. 一個 Sprint 結束時，在 [看板列表](#看板) 更新狀態，並開下一個 Sprint 的看板。

## 標籤

| 標籤 | 用途 |
|---|---|
| `📢公告` | 範圍、決策、流程的變更 |
| `🚧進度` | 工作進度回報 |
| `✅完成` | 某個項目完成並已驗證 |
| `🔬驗證` | 技術驗證、實測結果 |
| `⚠️發現` | 實作或驗證中發現的問題、風險 |
| `⛔卡關` | 無法繼續、需要協助 |
| `❓待決定` | 需要人做決定 |
| `💡建議` | 改進想法，不急 |

## 留言格式

複製下面的格式，貼到看板「💬 留言區」的最上方：

```markdown
### #編號 · 標題

> 👤 **發文者** · 🕒 YYYY-MM-DD HH:MM · `🚧進度`

內容（做了什麼、結果、連結）。

<details>
<summary>💬 回覆（0）</summary>

（尚無回覆）

</details>

---
```

回覆時，把 `<details>` 裡的「（尚無回覆）」換成以下格式，並更新摘要上的回覆數：

```markdown
> ↳ 👤 **回覆者** · 🕒 YYYY-MM-DD HH:MM
>
> 回覆內容
```

- 時間使用台灣時間（UTC+8）。
- 發文者寫名字；AI 寫 `Claude（AI）`。
