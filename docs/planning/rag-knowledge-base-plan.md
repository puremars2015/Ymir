# RAG 知識庫後續開發計畫

- 記錄日期：2026-10-07
- 狀態：**需求與架構方向已記錄；尚未實作，待後續執行**
- 本次僅更新規劃文件，不安裝模型、不建立資料庫、不變更程式或部署。

## 已確認的需求與架構方向

使用者提供文件，系統擷取內容、建立向量索引並提供 RAG 問答，讓使用者根據自己提供的資料詢問問題。回答需提供來源資訊，方便回到文件確認。

1. **Embedding 獨立容器**：平台共用一個向量化服務，不為每位使用者或每個任務重複載入模型；日後可獨立擴充服務容量。
2. **每個專案一份 SQLite 向量資料庫**：同一使用者可建立多個專案，各專案的文件與索引互相隔離。同專案的匯入、更新及問答任務共用該專案資料庫，不以單次 Agent execution 建立新資料庫。
3. **預設 SQLite，外部服務可選**：透過向量儲存抽象介面，讓專案在必要時選用單位／使用者獲授權的共用獨立向量資料庫服務。
4. **RAG 服務由平台管理**：依專案的向量儲存設定執行檢索與生成。建立專案索引即啟用該專案的問答能力，不必替每個專案產生一套服務程式或容器。
5. **持久保存**：文件、索引與設定不隨任務結束或 Agent 容器閒置停止而刪除；服務重啟後仍可查詢。

目前 `/make`、workspace 檔案下載、Pi Agent 與 LiteLLM 已存在，但尚無知識庫文件匯入、Embedding 呼叫、向量儲存轉接器或 RAG 查詢流程。本功能屬新增平台能力，不應假設目前 MiniMax 的對話端點也提供 Embedding。

## 使用流程

### 文件匯入與索引

1. 使用者選擇或建立專案，進入「知識庫」並新增文件；沒有專案的對話先選擇／建立專案，不默認跨專案合併資料。
2. 平台驗證專案權限與文件格式、大小，保存原始文件及版本，建立可持久恢復的索引工作。
3. 背景工作擷取文字，保留檔名、頁碼或章節等可取得的來源資訊；把內容切成可檢索段落。
4. 呼叫共用 Embedding 服務，將段落轉成向量，寫入該專案選定的向量儲存。
5. 新版本完整建立後才成為可查詢版本，介面顯示「處理中／可查詢／失敗」，並提供重試。失敗不得把半成品標成已完成。

### 根據文件問答

1. 使用者在專案知識庫問答入口提問，或在專案對話明確選擇使用知識庫。
2. 後端驗證身分、專案與知識庫權限，使用與索引相容的 Embedding 模型向量化問題。
3. 只在指定專案的有效索引中搜尋相關段落；RAG 服務組合問題、相關內容與回答指示，交給回答模型生成答案。
4. 回傳回答與引用來源，引用定位到實際使用的文件版本及段落。資料未涵蓋問題或檢索不足時明確說明，不將一般推測當成文件中的結論。
5. 多輪問答可使用該對話的上下文理解追問，但每次都重新檢查專案權限與檢索範圍，不沿用其他專案的內容。

### 更新與移除

- 同一文件更新後建立新索引版本，成功才切換；避免新舊版本片段混在同一答案中。
- 移除文件時同步移除／停用對應索引，後續查詢不得再引用；歷史回答與來源保存政策需另行確認。
- 提供索引重建與失敗重試，工作狀態與實際索引版本可在服務重啟後對帳，避免重複段落。

## 元件分工與資料隔離

```text
使用者 → Ymir 專案知識庫介面 → RAG 模組（登入／專案權限／工作狀態）
                                  │
                     文件保存 → 擷取文字／切段背景工作
                                  │
                                  ├→ 共用 Embedding 容器
                                  │
                                  ├→ 專案 A：SQLite A
                                  ├→ 專案 B：SQLite B
                                  └→ 專案 C：獲授權的外部向量服務／專案專屬索引

提問 → 問題向量化 → 指定專案檢索 → 回答模型（現有模型入口）→ 答案＋引用
```

| 元件 | 責任與保存範圍 |
|---|---|
| Ymir RAG 模組 | 專案權限、文件清單、索引工作、問答流程及引用；沿用平台身分與稽核 |
| 文件與索引背景服務 | 受控保存文件、擷取文字、切段、產物版本、重試及恢復；不依賴 Agent 任務保持執行 |
| Embedding 容器 | 文件段落與問題向量化；模型權重使用持久 volume，只在內部提供 API |
| SQLite 向量儲存 | 每個專案獨立檔案，保存向量、段落及來源對應；需要向量搜尋擴充，SQLite 本身不能等同已具備向量搜尋引擎 |
| 外部向量服務 | 依專案設定使用 provider／連線設定與隔離索引；不可讓使用者任意連到平台未授權的內部位址 |
| 回答模型 | 根據檢索內容生成答案，與 Embedding 分工；用量與費用應納入平台管理 |
| 平台 SQL Server | 知識庫設定、文件版本／工作狀態及授權等管理資料；不因使用 SQLite 而替換既有平台資料庫 |

預設資料布局為受平台管理的持久目錄，例如 `knowledge/<ownerId>/<projectId>/vectors.sqlite`，搭配受控的文件保存目錄。這是規劃示例，實際根目錄由部署設定決定，只能由平台 ID 推導。原始文件與 SQLite 不放進 Agent 可任意修改的 workspace，也不掛載給 Agent；如要匯入既有 workspace 成果，需經過擁有者驗證及受控複製介面。

RAG 檔案服務以專用持久 volume 存取文件與 SQLite。依 [ADR-0008](../adr/0008-containerized-api-runtime-host.md)，不得因此把使用者 workspace 或容器管理 socket 掛到 API；服務拆分與 volume 邊界需在新 ADR 確認。Agent 若要呼叫知識庫，後續新增受權限限制的查詢工具，不把資料庫憑證或 SQLite 原始路徑交給 Agent。

SQLite 由單一儲存服務管理，依專案協調索引寫入，設定 busy timeout／重試並評估 WAL；不同使用者透過服務查詢，不各自直接打開檔案。WAL 的併發仍受單一 writer 限制，不把運作中的 SQLite 放在 SMB／NFS 或 OneDrive 同步目錄共同開啟。備份採一致性快照，不只複製可能尚有 WAL 的單一 `.sqlite` 檔。

## 可切換的向量儲存與模型設定

### 向量儲存介面

新增平台內部的向量儲存介面，至少包含建立／檢查索引、寫入段落向量、刪除文件版本、搜尋及索引健康狀態。RAG 流程不依賴 SQLite 的 SQL 語法或特定外部產品的 API。

- SQLite 是首版預設 provider；`sqlite-vec` 是候選擴充，實作前驗證 .NET 整合、Windows／Linux native library、版本相容性與實際檢索效能。
- 外部 provider 的連線、憑證與可選範圍由管理者設定，使用者／專案只選擇獲授權的設定。單位概念目前未完整定義，跨單位管理與租戶模型需另行設計。
- 各 provider 都必須在後端強制專案邊界；不可只靠前端傳入的 collection 名稱，或先搜尋所有資料再於生成後過濾。
- 外部儲存共用服務時，仍需以專案專屬 collection／namespace 或 provider 可強制的過濾機制隔離；每個專案記錄 provider、受控索引識別與索引版本。
- 切換儲存必須複製或重建完整索引、驗證成功後才切換，失敗保留原設定。切換 provider 不代表既有資料會自動搬移，也不代表不同 provider 的分數可直接比較。

### Embedding 與回答模型

- 記錄索引使用的模型名稱、固定版本、向量維度、文件／問題前處理及切段策略版本。文件與問題必須使用相容設定；變更模型或維度時建立新索引，不混用新舊向量。
- 模型選擇以實際文件語言（含繁體中文）、檢索品質、授權、硬體與可承受延遲決定；CPU／GPU 及模型大小尚未選定，不預先承諾處理速度。
- 共用服務需支援批次向量化、併發限制、健康檢查與逾時，文件匯入排隊不應無限制阻塞即時提問。
- Embedding 在本機執行只代表向量化留在本機；若使用外部回答模型，檢索片段仍會送給該模型。資料可否外傳、回答模型選擇與用量／預算檢查需確認後才能啟用。

## 預定介面、授權與首版範圍

新增能力而非既有端點：專案知識庫設定／狀態、文件上傳或受控匯入、文件列表與移除、索引進度／重試／重建，以及 RAG 查詢與來源查閱。查詢輸入須包含受驗證的專案上下文，輸出包含回答、引用及資料不足提示；串流方式可沿用 SSE，實際契約於實作前補入 SA／API 快照。

管理者介面預留 Embedding 服務設定、可選向量 provider、容量／文件數／用量限制；憑證只能寫入、不可回顯。任何使用者不得透過此功能任意傳入主機路徑、外部 endpoint 或明文資料庫憑證。

- **首版預設私人**：只供專案擁有者匯入與查詢，不因網站已分享而自動分享知識庫。指定使用者或公司共用知識庫是可擴充方向，是否納入首版待使用者確認。
- 所有文件、引用、索引工作及問答端點都要在 server 端驗證權限；同一使用者切換專案仍不得跨專案檢索。分享若實作，需分開定義查詢與管理權限，以及來源原文能否查看。
- 文件視為不可信資料，限制格式、檔案大小、解壓縮／解析資源及來源路徑，解析程序不可任意執行巨集或文件程式碼。文件中的指令只能作為引用資料，不能改變系統權限或觸發 Agent 工具。
- 初期格式建議文字型 PDF、DOCX、TXT、Markdown；掃描 PDF／圖片 OCR、舊版 DOC、試算表、網址擷取及即時 OneDrive 匯入另列後續，錯誤應清楚顯示「不支援」或「無可擷取文字」。
- 私人文件、段落及向量不提供公開下載；log／稽核只記必要識別與狀態，不預設保存全文、完整問題或模型憑證。

## 後續開發階段與驗收

| 階段 | 內容與完成條件 |
|---|---|
| 1. ADR 與技術驗證 | 選定 Embedding 模型／硬體、SQLite 擴充及 native 部署；以繁體中文樣本驗證擷取、切段、向量搜尋與引用；確定服務／volume 邊界與權限 |
| 2. 最小文件索引 | 專案知識庫、持久文件儲存、背景工作、獨立 Embedding 容器與每專案 SQLite；完成匯入、狀態、失敗重試、文件更新／刪除 |
| 3. RAG 問答 | 專案檢索、回答模型、引用查閱、資料不足提示及上下文處理；介面可從專案知識庫提問並顯示進度／答案 |
| 4. 外部向量 provider | 選定第一個外部 provider，管理者配置、專案選用、隔離／健康檢查及受控索引遷移；RAG 使用相同介面 |
| 5. 分享與擴充 | 依後續決定加入知識庫分享、Agent 查詢工具、OCR／額外格式、OneDrive 匯入、配額／監控與更多 provider |

驗收至少包含：

1. 同一使用者的專案 A、B 各有自己的 SQLite；相同問題只取得當前專案的內容，其他使用者也不能存取。
2. 同一專案連續任務沿用索引；Agent 停止、重建或平台重啟後，原始文件及有效索引仍存在且可查詢。
3. 上傳支援格式可完成擷取、切段與索引；空白、掃描／不支援格式、超限、解析錯誤均有可理解的狀態，不產生假成功。
4. 以固定測試文件驗證相關段落召回、回答與引用對應；不在文件中的問題有資料不足提示。切段不能任意宣稱有原文件不存在的頁碼。
5. 更新成功後只查詢有效新版本；移除文件後不再召回；失敗、取消、重試及重啟恢復不重複加入片段或破壞原索引。
6. 索引與查詢同時執行、SQLite 鎖定、Embedding 逾時／停止、回答模型失敗／預算不足等情境可恢復並給出摘要錯誤。
7. 換 Embedding 模型／維度不能查詢不相容索引；重建與 provider 切換失敗保留原有效版本。
8. 外部 provider 與 SQLite 通過同一組新增、查詢、刪除及專案授權測試；外部服務的 shared collection 不會洩漏其他專案資料。
9. 文件內含惡意指令、路徑穿越或隱藏憑證時，不取得額外權限、不執行文件程式、不把敏感內容寫入 log。
10. 文件與 SQLite 一致性備份可恢復；向量服務僅內部可用，知識庫 API 受平台登入與授權管理。

單元及整合測試使用 Fake Embedding／Fake LLM 與固定文件；真實模型另外建立可重現的繁體中文檢索評估，不在一般測試中呼叫付費模型。首版評估樣本、品質門檻、容量及延遲目標需在技術驗證階段記錄，不以未測試數字作承諾。

## 實作前待確認與參考

- Embedding 模型、模型授權、CPU／GPU／記憶體、是否允許下載模型，以及文件送交外部回答模型的政策。
- 第一個外部 provider 與可選服務的管理範圍；單位／租戶的識別、權限與配額。
- 文件格式、檔案／專案容量、每次檢索數量與切段設定；專案封存／刪除、原文及歷史引用的保留政策。
- 知識庫分享是否納入首版，以及分享者能否查看來源原文；與 [前端網站託管計畫](frontend-site-hosting-plan.md) 的 API 授權整合另行設計。
- 本功能不依賴 [OneDrive Workspace 計畫](onedrive-workspace-plan.md)。未來可以受控匯入文件，但不直接用 OneDrive 同步運作中的 SQLite。
